# 路由模式拦截测试

`sr_mode_probe.conf` 是临时诊断配置，不是可以依赖的生产拦截配置。它只设置测试域名及测试 IP，不屏蔽其他服务目标。不要将它当作账户或出口保护措施长期使用。

## 测试目的

Shadowrocket 手册说明 `pre-matching` 会在正常规则匹配之前执行 REJECT，但没有明确说明所有规则类型在全局代理模式中的行为。此测试用于收集目标设备的实际证据，静态解析、下载成功和其他代理内核的测试都不能代替它。

依据：[Shadowrocket 策略扩展参数](https://github.com/LOWERTOP/Shadowrocket/wiki#策略扩展参数)。

## 操作

1. 先记下当前配置、路由模式和节点。关闭需要保护的应用，测试期间不访问其网站。
2. 使用平时已确认可用的海外节点，先确认下表测试地址在原配置下可以访问或建立连接。原本不可达的地址不能用于判断拦截是否成功。
3. 导入测试配置并使用。分别在「配置」和「代理」模式测试，每次切换后断开再重连，以减少旧连接的影响。
4. 查看 Shadowrocket 的代理/连接日志，记录目标、策略是否为 REJECT、命中的规则，以及当前模式。网页打不开本身不是拦截证据。
5. 完成后恢复原配置和路由模式。

| 地址 | 条件 | 配置模式预期 | 代理模式 |
|---|---|---|---|
| `https://example.com/` | 后缀 + pre-matching | REJECT | 待实测 |
| `https://example.org/` | 关键词 + pre-matching | REJECT | 待实测 |
| `https://1.0.0.1/` | IPv4 + pre-matching | REJECT | 待实测 |
| `https://[2606:4700:4700::1001]/` | IPv6 + pre-matching | REJECT | 待实测；先确认网络支持 IPv6 |
| `https://example.net/` | 普通后缀，无 pre-matching | REJECT | 普通规则对照项，预期被代理模式跳过 |

IP 地址使用 Cloudflare 的公共解析器地址作为无账号测试目标。只验证连接策略，不以 TLS 错误、超时或页面内容判断成功。此配置会在测试期间阻断到这些 IP 的匹配流量。

只测浏览器的几个连接还不能证明应用全部流量都被拒绝。正式配置仍需验证实际使用版本、TCP/UDP、IPv4/IPv6、已有连接与新连接，以及域名不可见的情况。若任意必需规则类型在全局代理模式下没有实际拒绝证据，就不能标记为双模式保护。
